# pair-wise-yf-54 博物馆展品点交与布展条件核验

## 源提示词摘要
策展人、保管员、布展负责人和借展方从到场点交、环境条件检查、安装位置确认到闭展归还共同处理展品。系统记录条件、附件、风险等级、照片说明、处理意见和签字结果，差异项未解决时不能进入下一阶段，并支持大量展品与断网暂存。

## 技术栈
Vue 3 + TypeScript + Vite + Vuetify + Pinia + Vue Router + Axios + VueUse + VeeValidate + Zod + Vue I18n。

## 已实现闭环
- 展品、环境检查、差异项三类业务对象，每件展品带 `version` 基线版本。
- 到场点交、布展核验、闭展归还的分阶段签字与推进门禁。
- 未解决差异阻断流转，可单独确认解决。
- `v-virtual-scroll` 大列表、离线队列提示、手动确认同步。
- localStorage 持久化（v2 schema，自动兼容旧 key 的 v1 数据）。

## 离线续作（字段级合并）
- 每条离线操作记入带编号的本地批次，包含**改动字段、设备号、基线值**；顶栏可切换三台设备（保管员 ×2、借展方 ×1）并模拟断网/回网。
- 回网后按批次开建顺序回放，逐字段三方合并（基线 / 已提交 / 离线新值）：
  - 两边改**不同字段**：各自落库，版本叠加；
  - 同一字段两边改成**不同值**：预扫描生成冲突单，两版（含三版）都保留，任何一方都不覆盖，在「字段冲突」页确认保留哪一版。
- 签字绑定**当时的展品内容**（阶段、版本、条件、环境、附件、差异项的 FNV 哈希）：环境、附件、差异项在签字后有改动即剪枝失效，必须重新签字。
- 推进/归还门禁同时拦截：未解决差异、缺任一方签字、签字版本对不上、字段冲突未确认、借展方设备越权替保管员签字（记录时拦截 + 回放时二次拦截）。
- 合并失败的批次本地不丢、标为「合并受阻」，在「离线批次」页**按离线编号重试**；冲突确认后自动重放同批次的推进/归还。
- 升级兼容：v1 数据（只有 `signed` 角色数组）迁移到 v2 时归并基线版本 v1，按现有签字和阶段补算内容哈希的 migration 签字，并为每件展品补一条「来源记录」。
- 「来源记录」页可查建档、合并、冲突确认、推进、归还、迁移的完整轨迹。

## 代码结构
- `src/services/offline.ts`：类型、内容哈希、签字校验、门禁判定。
- `src/services/merge.ts`：批次投影、预扫描分叉、三方合并、冲突确认、批次重试。
- `src/services/migration.ts`：v1 → v2 数据迁移。
- `src/stores/exhibition.ts`：Pinia 状态、设备视角（`view` getter 叠加本机开放批次）、全部动作。
- `src/components/`：展品详情、字段冲突、离线批次、来源记录四个面板。
